# Current-Version Engineering Audit — Dungeons

- **Audited revision:** `194f4f0`
- **Application version:** 0.9.3
- **Audit date:** 2026-07-27

## Scope

Simulation correctness, rendering and animation, input, UI, accessibility,
PWA/build configuration, leaderboard client/server, security, licensing,
documentation, test strategy, and CI.

## Executive verdict

This is not "vibe code." The deterministic simulation, explicit event boundary,
architecture tests, balance simulator, UI tests, and browser campaign are unusually
disciplined for a small game. The current release nevertheless has several concrete
correctness and production-readiness problems. The highest priorities are stair
actions not incrementing the leaderboard turn counter, incomplete GPL distribution
materials, global CSS disabling pinch zoom despite comments claiming otherwise, the
real-browser campaign not running in CI, and a leaderboard backend that is both
honor-based and weakly abuse-resistant.

## What is already strong

- One seeded RNG and one authoritative state object make runs reproducible.
- Simulation code returns events and does not manipulate Phaser.
- Movement and diagonal corner rules are shared rather than duplicated.
- Entity turn order is explicitly sorted by ID instead of relying on Map order.
- Floors preserve maps, visibility, items, entities, and ID allocation on revisit.
- Architecture tests enforce seeded randomness, Phaser isolation, and network,
  storage, and renderer boundaries.
- The test portfolio covers simulation, balance, UI, input, networking, server
  validation, renderer-pure logic, and a substantial browser campaign.
- Renderer layers have explicit depth ordering and retain an ASCII fallback.
- Camera follow and click unprojection distinguish animated position from settled
  simulation position, a good response to movement/camera jitter.
- Modal overlays use dialog semantics, aria-modal, focus trapping, and focus restore.

## P0-1: Stair moves do not count as turns

Evidence:

- `src/core/turnEngine.js:37-79` returns immediately when either stair step changes
  floor.
- `src/core/turnEngine.js:120-132` increments `state.turn` only in `advanceWorld()`.
- `src/main.js:104-114` submits `state.turn` as the leaderboard tie-break value.

Impact:

Every floor transition is a successful movement action but is omitted from the turn
count. Equal-floor leaderboard scores are ordered by fewer turns, so the bug
artificially improves scores. Repeated transitions between visited floors also
represent real actions that never appear in the submitted count.

Recommendation:

Separate "consume one successful player command" from "advance consequences on the
departed floor." Increment exactly once after a successful player action, then allow
a stair transition to skip old-floor visibility/enemy/pickup phases.

Required tests:

- descent increments exactly once;
- ascent increments exactly once;
- a Ring-of-Speed second-step stair arrival increments exactly once;
- old-floor enemies do not act on a transition;
- arrival-floor pickups do not resolve immediately;
- invalid movement does not increment;
- submitted payload carries the corrected count.

## P0-2: GPL distribution material is incomplete

Evidence:

- CREDITS.md identifies upstream artwork, a pinned commit, paths, hashes, GPLv3
  provenance, and derived icons.
- The repository has no LICENSE or COPYING file.
- CREDITS.md says the distribution is under GPL-compatible terms but does not clearly
  declare a precise project-wide license for original source.

Recommendation:

The maintainer must first confirm ownership and intended licensing. Then add the full
license text (likely GPL-3.0-or-later if that is the intended compatible choice), a
clear README license statement, retained upstream notices, and unambiguous treatment
of original code, unmodified assets, and derived icons. Ensure deployed/downloadable
distributions retain the license and credits. Do not have an agent invent copyright
holders.

## P1-1: Pinch zoom is disabled despite the accessibility comment

Evidence:

- `index.html:5-8` says pinch zoom remains enabled.
- `index.html:56-68` applies `touch-action:none` to html and body.

Impact:

Global `touch-action:none` blocks browser pinch zoom on touch devices, including DOM
help, menu, leaderboard, and death-screen content that low-vision users may need to
magnify.

Recommendation:

Restrict gesture suppression to the Phaser canvas/game surface. Allow normal gestures
or `touch-action:manipulation` on overlays, verify overlay scrolling, test mobile
Chromium and WebKit, and add a static regression check rejecting global gesture
suppression.

## P1-2: Browser integration tests are not automated in CI

Evidence:

- `.github/workflows/test.yml` runs lint, format checking, and unit tests only.
- `.github/workflows/deploy.yml` runs unit tests and build, but not lint, format, or E2E.
- `npm run test:e2e` currently depends on an externally available Chromium executable.

Impact:

The only tests capable of validating Phaser, sprite/camera motion, pixel-to-tile
conversion, browser input, service workers, and offline boot are optional. Those are
exactly the highest-risk areas after the recent rendering and animation changes.

Recommendation:

Add a pinned Playwright browser installation, a fast PR smoke suite, and the full
parity/offline campaign on main, nightly, or pre-release. Upload traces/screenshots on
failure and make production deployment depend on the appropriate quality gate.

## P1-3: Leaderboard integrity is honor-based

Evidence:

`server/scores.js` validates shape and bounds but trusts claimed floor, turns, seed, and
version. Anyone can directly POST a syntactically valid fabricated score.

Recommendation:

Choose explicitly:

A. Honor board: label it as casual/unverified, provide moderation/deletion tools, and
add basic duplicate/spam controls.

B. Verified board: submit a compact command log plus ruleset/version and server-issued
nonce, replay the deterministic simulation server-side under strict body/time
limits, and compare the claimed result. A secret embedded in browser JavaScript is
not an anti-cheat mechanism.

## P1-4: Leaderboard server hardening

Findings:

- The in-memory rate limiter is isolate-local and cannot enforce a global limit.
- Its Map retains keys for every observed IP and does not prune empty entries.
- Missing `ALLOWED_ORIGIN` falls back to `Access-Control-Allow-Origin: *`.
- D1 failures escape the JSON/CORS response path.
- The worker reads the complete body before checking a limit named `MAX_BODY_BYTES`;
  JavaScript string length is not encoded byte length.
- The server does not return `Retry-After` with 429.

Recommendations:

Use Cloudflare-native rate limiting, Durable Objects, Turnstile, or another shared
mechanism for meaningful abuse control. At minimum prune the local Map. Require an
explicit production origin and fail closed. Normalize storage errors into generic
JSON 500 responses with CORS and no-store headers while logging a request ID. Check
`Content-Length` early, enforce an actual byte limit, require JSON where appropriate,
and provide `Retry-After`.

## P1-5: Leaderboard client retry and concurrency bugs

Evidence:

- `src/net/leaderboard.js` queues every POST failure, including permanent 4xx errors.
- `flushQueue` stops on the first failure and keeps that entry plus every later entry.
- GET and POST requests have no timeout or cancellation.
- boot and repeated `online` events can invoke `flushQueue` concurrently without a lock.

Impact:

One permanently invalid queued payload can poison the queue forever. Concurrent
flushes can duplicate submissions, and stalled fetches can leave UI operations
pending indefinitely.

Recommendation:

Retry network errors, timeouts, 408/425/429, and selected 5xx responses. Discard or
surface most permanent 4xx responses and continue to later entries. Respect
`Retry-After`, add AbortSignal-based timeouts, return structured failure reasons,
version the queue schema, and serialize flushes through one shared in-flight promise.

## P1-6: Avoidable dynamic innerHTML sinks

Evidence:

- `src/ui/messageLog.js` interpolates formatted event data into HTML strings.
- `src/ui/hud.js` accepts trusted icon HTML and interpolates state values into HTML.
- `src/main.js` derives the icon string from internal sprite metadata.

Current data is controlled, so this is not presented as a known exploitable XSS.
It is nevertheless a fragile trust boundary that can become unsafe when saves, mods,
custom names, or network data are added.

Recommendation:

Return icon Elements rather than `outerHTML`, build the HUD and log with
`createElement`, `textContent`, style properties, and `replaceChildren`, and add
hostile-string tests.

## P1-7: Documentation and audit drift

Findings:

- README.md still names Tengu although the shipped boss is the evil Eye.
- README's renderer tree omits autotiling, sprite layers, entity frames, facing,
  motion, and UI-icon metadata.
- QC_REPORT.md describes an old audited commit/version and can be mistaken for a
  current certification.

Recommendation:

Correct README terminology and architecture, document lint/format/E2E commands, and
archive historical audits under immutable dated/versioned filenames with a prominent
audited SHA and historical-snapshot warning.

## P2-1: Spawn placement contracts are inconsistent

`src/entities/spawn.js` says nothing shares a tile, but `randomFreeFloorInRoom` checks
terrain and entities only. Potion/chest callers check item overlap after selection and
skip the spawn; secrets use a different retry wrapper. This creates misleading names,
duplicated checks, inconsistent retry semantics, and avoidable under-spawning.

Recommendation:

Create one configurable placement primitive with explicit entity/item blocking and
attempt behavior. Add broad-seed invariants for no overlap and track generation
shortfalls in simulation/debug output.

## P2-2: Stair-arrival clearing has an invalid-state fallback

`src/core/gameState.js` bounds its relocation BFS. On total failure the enemy remains
on the arrival stair, after which the player is attached to the same coordinate.
Current generation likely makes this unreachable, but assumption drift should not
produce overlapping entities.

Recommendation:

Return success/failure, search the full reachable component or apply a deterministic
fallback, assert in development, and add an invariant test that transitions never
leave overlapping entities.

## P2-3: Turn-order comments are historically numbered

`advanceWorld` labels early visibility as Step 5, then enemies as Step 3 and pickups as
Step 4. The behavior is explained and tested, but stale numbering increases
maintenance risk. Replace historical numbers with descriptive stage names or update
the authoritative specification and code together.

## P2-4: Bundle and source-map policy

Observed production build:

- main JavaScript: approximately 1.54 MB, 362 KB gzip;
- source map: approximately 10.49 MB;
- PWA precache: approximately 1.59 MB.

Phaser explains much of the bundle. The concern is lack of an explicit regression
budget and an elevated warning threshold rather than size alone. Production source
maps are always emitted and uploaded with the Pages artifact.

Recommendation:

Track compressed bundle/precache size and mobile cold-load/parse/boot metrics in CI.
Keep public maps if transparent debugging is intentional; otherwise use hidden maps
or disable them in public production. Document the policy rather than leaving it
implicit.

## P2-5: Tooling and CI coverage are inconsistent

Findings:

- `npm run format` writes JS, MJS, JSON, and Markdown globally, while `format:check`
  checks only selected JS paths.
- `lint` omits `e2e/*.mjs` and root executable configuration such as `vite.config.js`.
- There is no one-command ordinary quality gate.
- Direct main deployment does not enforce lint or formatting.

Recommendation:

Add "check" (lint, format:check, unit tests, build) and "check:full" (check plus E2E),
make write/check globs agree, include MJS and root config in ESLint, and invoke the
shared scripts from PR and deployment workflows.

## P2-6: Test strategy improvements

- Add branch coverage with conservative thresholds and ratchet upward.
- Add generated invariants: no overlaps, in-bounds/walkable entities, legal A\* steps,
  exactly-one turn per successful command, no state/RNG change on invalid commands,
  transition persistence, and same-seed/same-command state equivalence.
- Add selective mutation tests for RNG, movement, turn consumption, score validation,
  damage mitigation, and secret planning.
- Add coarse generation and pathological-turn performance budgets.
- Do not optimize for a vanity 100% coverage number; protect high-risk boundaries.

## P2/P3 runtime defensive improvements

- `randomSeed` assumes Web Crypto. Detect absence and show an unsupported-browser error
  or use a clearly non-security fallback without introducing gameplay `Math.random`.
- `window.__game` exposes the complete state. Keep it if transparent debugging is a
  deliberate policy; otherwise use development/test instrumentation. Hiding it is not
  anti-cheat because the POST endpoint itself is spoofable.
- `server/worker.dashboard.js` is a hand-maintained duplicate. Generate it from modular
  source and verify generated output in CI rather than relying only on drift tests.
- Before adding persistent runs, define how service-worker autoUpdate interacts with
  ruleset versions, run compatibility, and migrations.
