# Current-Version Engineering Audit — Dungeons

- **Audited revision:** `b7e66f7`
- **Application version:** 0.9.8
- **Audit date:** 2026-08-01

## Scope

The three releases that had never been independently reviewed — **0.9.4** and
**0.9.5** (remediation of the 2026-07-27 audit), **0.9.6** (ring rebalance and
End run), **0.9.7** (stair-safe auto-walk, corridor click alignment) and
**0.9.8** (the two Secrets quirks, the difficulty band) — plus a re-check of the
previous audit's own acceptance criteria. Simulation correctness, rendering and
animation, input, UI, accessibility, PWA/build configuration, leaderboard
client/server, test strategy and CI.

## Executive verdict

The simulation layer came through this audit clean: **no P0 and no P1 findings**,
with every candidate at that level refuted under adversarial checking. That is a
genuine result, not an absent one — it was established by ~275k commands of
randomized play across 550 seeds, 7,272 click-paths walked to completion on 720
real floors, byte-level replay determinism over 120 seeds, and FOV symmetry over
20,444 origin/target pairs, all asserting the documented invariants every turn.

The defects that exist are concentrated in the layers **around** the simulation,
and they share a shape: mechanisms that were designed correctly, then given a
guard, an index or a predicate that is subtly narrower than the thing it is
guarding. The offline queue anticipated a submit-during-drain race and computed
the overlap by array index, which the cap silently invalidates. The click
correction was written for sprite terrain and applied to both renderers. The
HTML-sink guard bans template-literal splicing while the codebase already used
concatenation. The boss-chest relocation, added in 0.9.7 to stop items stacking,
fell back to the one tile it had just rejected.

The most serious single finding is **P1-1**: reading `window.localStorage` at
module scope in the composition root, which throws — not returns null — when a
browser has blocked site data, aborting the module and leaving a blank page. It
is the identical failure mode `randomSeed` was fixed for in 0.9.5, in the twin
dependency, left unguarded.

## What is already strong

- **State ownership is structural, not aspirational.** The floor cache shares
  object references with the live floor rather than copying, so "a cached copy
  that can desync" is unrepresentable; `restart` resets in place so every holder
  stays pointed at the live run.
- **RNG discipline holds under adversarial reading.** No `Math.random` under
  `src/`; `world/secrets.js` derives a local stream so band plans cannot shift
  the main draw order; every relocation scan (`dropBossChest`, `dropRing`,
  `ensureArrivalClear`) is a deterministic DIRS8/BFS walk with zero draws. The
  "load-bearing, do not clean up" comments in `spawn.js` about draw ordering are
  accurate and earned.
- **One definition per rule.** `diagonalAllowed` is the single corner rule, and
  `meleeReachable(A,B)` / `meleeReachable(B,A)` provably test the same two tiles
  — the 0.9.2 fix is symmetric by construction. `hiddenFromEnemy` really is the
  single Shadow predicate, correctly AND-ed with true line of sight so the ring
  cannot leak into aggro.
- **FOV** is exact-rational symmetric shadowcasting with no floating point in
  the slope math, and it holds up empirically. **A\*** is deterministic by design
  (heap tie-broken by node id) and its octile heuristic stays consistent under
  the corner-cut edge removal, so the closed-set short-circuit is sound.
- **Layer separation holds.** No write to simulation state anywhere in
  `renderer/`, `ui/` or `input/`; no gameplay call in any tween or animation
  callback; `ui/` never imports `renderer/`, with `uiIcons.js` + `main.js`'s
  `spriteIconEl` a one-way bridge that hands over Elements, never markup.
- **The DOM trust boundary is real.** Every leaderboard cell goes through
  `textContent`, HUD and log are `createElement` + `replaceChildren`, initials
  are sanitised on input _and_ re-sanitised on submit, and the CSS clips a
  hostile `version` string rather than letting it break the layout.
- **`overlay.js`'s modal contract** — Tab trap scoped to the overlay element so a
  layered child never fights the one below, focus restore, `aria-live` status —
  is correct and well-reasoned.
- **The worker's failure modes all close the right way**: CORS fails closed with
  a wildcard only as a _configured_ value, D1 errors normalized into JSON so the
  client can classify rather than see an opaque network error, `no-store` on
  500s, no internals leaked, fully parameterized SQL.
- **The generated dashboard worker is guarded on two different axes** —
  behavioural parity battery _plus_ byte-identity against a fresh generation.
  This is the correct answer to "a hand-inlined copy drifts".
- **Broad-seed invariants** are the highest-value suite in the repo, and
  self-awareness about vacuity is load-bearing: `invariants.test.js` type-checks
  `state.rng.s` before comparing it, and `gesturePolicy.test.js` documents why it
  uses `getPropertyValue`. Both historical vacuous tests are genuinely fixed.
- **The bundle budget is a real ratchet** (89%/89%), and the coverage config's
  refusal to exclude the barely-covered renderer modules is the right instinct.

## P1-1: `window.localStorage` at module scope can stop the game booting

`src/main.js:99` (pre-fix) passed `storage: window.localStorage` directly into
`createLeaderboardClient`, at module scope, unguarded. Reading the
`localStorage` **property** throws `SecurityError` in Chrome/Edge with site data
blocked and in Firefox with `dom.storage.enabled=false` — the throw happens
before any of the client's own `try`/`catch` can help. The composition root
module aborts, no Phaser game is created, and the player gets a blank page.

Every _use_ of storage inside the client is already defensive
(`leaderboard.js:78-98`, `:191-205`); only the handle acquisition was not. This
is precisely the failure mode documented as fixed for Web Crypto at
`src/main.js:21-29` — "the throw happened at module scope, so the game didn't
start at all" — in the twin dependency.

**Fix:** acquire the handle through a `safeStorage()` helper that probes with a
`getItem` (Safari private mode throws on _use_, not on access) and falls back to
a no-op shim. The offline queue is then simply unavailable, which is the correct
behaviour on a browser that has refused storage.

## P1-2: remembered doors repaint from unseen enemy positions

`src/renderer/spriteLayer.js:84-86`. The `occupied` set is built from
`entitiesSorted(state)` with no visibility filter, and `apply()` draws any cell
that is `visible || explored` — so a door the player only _remembers_ still
repainted live from enemy positions. Demonstrated against the real module:

```
door REMEMBERED (not in LOS), no enemy    : frame 112 (RAISED_DOOR),      dim
door REMEMBERED (not in LOS), enemy in it : frame 113 (RAISED_DOOR_OPEN), dim
```

A player standing in one room watches a remembered doorway across the map swing
open and shut as an unseen goblin walks through it. That is an enemy-position
leak, and it cuts against a deliberate rule: doors are opaque
(`isTransparentTile` excludes `DOOR`) _precisely_ so what is in a doorway is
unknowable until you stand in it, and `syncEntities` already hides out-of-view
enemies. Only the terrain layer leaked. Sideways doors are worse, since the
lintel appears and disappears.

**Fix:** gate the `isOpen` predicate on the cell's own lighting
(`occupied.has(i) && (this.sightAll || visible[i])`), preserving both the
open-while-occupied effect for doors you can see and the Ring of Sight's reveal.

## P1-3: vendored art is precached with `revision: null` and can never update

`vite-plugin-pwa` sets `dontCacheBustURLsMatching = /^assets/`, and the SPD
sheets live under `public/assets/`, so they ship to `dist/assets/...` and match —
**even though their filenames carry no content hash**. The built `sw.js` shows
the asymmetry directly:

```
{url:"assets/sprites/warrior.png",          revision:null}   ← unhashed, no revision
{url:"assets/environment/tiles_prison.png", revision:null}   ← unhashed, no revision
{url:"icons/icon-192.png",  revision:"f7e58d32…"}            ← public/icons, revisioned
```

A revision-less precache entry whose URL is unchanged is never re-fetched. If a
sheet is ever re-vendored or edited — 0.7.1 re-skinned the boss, 0.7.4
regenerated the icon art, so this is not hypothetical — **every already-installed
PWA keeps serving the old PNG indefinitely**, with no recovery short of
uninstalling. Worse, `tests/entitySprites.test.js` validates frame rects against
the _repo_ PNG, so a frame-table change shipped with a new sheet passes CI green
while installed clients sample the wrong pixels or drop the whole cast to ASCII.

**Fix (any one):** move vendored art to `public/art/`; set
`workbox.dontCacheBustURLsMatching` to Vite's hashed-filename pattern; or import
the sheets through Vite so they get hashed. **Deferred** — see Remediation.

## P2-1: the offline queue loses a score submitted at cap during a flush

`src/net/leaderboard.js:155-157` computed "arrived during the drain" as
`readQueue().slice(snapshotLength)` — by array index. But `writeQueue` caps by
`slice(-QUEUE_CAP)`, which drops the **oldest** and shifts the array left, so
appending to a full queue leaves the index at or past the end and the slice
returns `[]`. The drain then writes that empty array over a score `submit()` had
already reported as `queued: true`, after the death screen told the player it
was saved. Verified repro at cap:

```
submit result:            { ok: false, queued: true, reason: 'http-500' }
queue right after submit: [2,3,4,5,6,7,8,9,10,999]
drain result:             { sent: 10, dropped: 0, kept: 0 }
queue after drain:        []          ← 999 gone
```

`tests/leaderboard.test.js` covered this exact race at _sub-cap_ length, where it
passes either way — which is how it hid.

**Fix:** track the payloads themselves in a closure array while a drain is in
flight, rather than deriving them from an index into storage.

## P2-2: `fetchScores` can hang forever; the timeout only covered headers

`request()` clears its abort timer in `finally`, then `fetchScores` awaited
`res.json()` **outside** the race. A response whose headers arrive but whose body
stalls leaves the promise pending indefinitely, and the leaderboard overlay sits
on "Loading…" with no recovery but closing the panel. `post()` is unaffected
(it never reads a body), so CLAUDE.md's "cannot hang the death screen" claim did
hold — the leaderboard _view_ was the exposed surface.

**Fix:** pass an optional `readBody` into `request()` and await it inside the
same deadline.

## P2-3: the click-alignment snap applied in ASCII mode too

`GameScene.screenToTile` called `pickClickTile` unconditionally, but `makeGrid()`
falls back to `GlyphGrid` when `RENDER_STYLE` is `ascii` **or the tilesheet fails
to load** — and glyph terrain has no overhang, since a `#` fills its own cell. In
that mode the snap redirected a click on a plainly-visible wall to the floor
below it and consumed a turn. The correction exists for the SPD art, so it must
be gated on that art being in use.

**Fix:** return the plain `worldToTile` when `useSprites()` is false — the same
predicate `makeGrid` already branches on. _(Found by automated review on PR #32
rather than by this audit; recorded here for completeness.)_

## P2-4: four latent couplings in the simulation layer

None reachable in shipped play; all are invariants held three modules away from
the code depending on them.

- **`dropBossChest`'s last-resort stacked items.** When the death tile failed
  `free()` and no DIRS8 neighbour was free, the drop fell back to the death tile
  — the one tile already known to fail. A boss dying on loot in a pocket stacked
  its chest on that loot, re-breaking the invariant the 0.9.7 relocation was
  written to protect. Unreachable on generated floors (bosses spawn in ≥4×4
  rooms). **Fix:** widen to a deterministic BFS in DIRS8 order, so ring 1
  resolves identically and "nowhere to put it" needs a floor with no free tile.
- **`resolveStairStep` ignored `ascend()`'s early return.** `ascend()` silently
  returns when `state.floor <= 1`, but the caller logged, pushed `ascendEvent`
  and returned `true` regardless — which skips `advanceWorld` entirely. A step
  onto a floor-1 up-staircase would consume a turn, emit a bogus "You ascend to
  floor 1", and hand the player a free, repeatable turn with no enemy phase.
  Unreachable: `TILE.STAIRS_UP` has one writer, `world/dungeon.js:46`, guarded by
  `floorNumber > 1`. **Fix:** `ascend()` reports whether it happened.
- **A failed `planPath` left the previous path installed.** All three failure
  exits returned `false` without clearing `state.path`. No live caller is bitten
  (every one calls `stopAutoWalk()`), but "returns false" reading as "the stored
  path is untouched" is a trap. **Fix:** null it first.
- **The boxed-in `dropRing` wore the ring silently.** No `pickupEvent`, no log
  line — the player read "a ring tumbles out!" and then nothing named which ring;
  the HUD chip was the only signal. **Reachable in ordinary play**, because the
  enemy phase runs before pickups: step into a dead-end alcove holding the chest,
  a chaser fills the tile behind you, every other neighbour is wall. **Fix:**
  emit the same event and log line the walked-over path emits.

## P2-5: the HTML-sink guard missed concatenation, and `menu.js` used it

`tests/architecture.test.js`'s guard was
`/\.(inner|outer)HTML\s*=[^;]*\$\{|insertAdjacentHTML\s*\([^;]*\$\{/` — it
requires a literal `${`. So:

```
MISSED   menu.js actual        insertAdjacentHTML('beforeend', '<div>v' + APP_VERSION + '</div>')
MISSED   hypothetical          el.innerHTML = '<b>' + row.initials + '</b>'
CAUGHT   template-literal form
```

Not exploitable today (`APP_VERSION` is a build constant), but the banned shape
was already present in a form the guard could not see, one non-constant value
away from shipping unflagged. **Fix:** ban concatenation into either sink as
well (requiring an identifier after the `+`, so joining string literals across
lines stays legal), and build the version line with `textContent`.

Noted in passing: `code()`'s comment stripper (`/\/\/.*$/gm`) truncates any line
containing a URL, since it eats the `//` in `https://`. Harmless for the current
guards but a trap for any future one that needs to match such a line.

## P2-6: the e2e escape tripwire and page errors did not gate

- `escaped.length === 0` appeared in the pass predicate of only 3 of 17
  scenarios. In **E10/death** — the one scenario that actually drives the
  leaderboard — and **E13/pwa** it was in the details string only.
- `pageErrors` was collected and printed but excluded from the exit condition, so
  an uncaught exception thrown on every boot passed as long as the DOM
  assertions still held.

On the `config.js` ↔ `runner.mjs:16` URL duplication: a mismatch **is** caught
today, but indirectly — the request falls through to the catch-all, is aborted,
the client classifies it as a network failure and queues it, so `posts.length`
fails. The residual risk is any _other_ cross-origin request introduced in E10 or
E13. **Fix:** add the tripwire to both predicates, gate the exit on
`pageErrors.length`, and add a unit assertion that the two URL literals match.

## P2-7: the lines/statements coverage floor was not binding

Measured 88.8% statements / 88.9% branches / 90.4% functions / 88.8% lines
against thresholds of `{ lines: 75, branches: 82, functions: 82, statements: 75 }`
— **13.8 points of slack** on lines/statements, room for roughly 650 lines to go
dark before CI noticed. CLAUDE.md's "a few points under the measured level
(~87%)" was true of branches and functions and false of lines and statements.
**Fix:** raise to `{ lines: 85, branches: 85, functions: 87, statements: 85 }`.

Minor: `scripts/check-bundle.mjs:61`'s `PRECACHED` regex hand-duplicates
`vite.config.js`'s `globPatterns`; adding `webp`/`woff` to one silently stops the
other counting it.

## P2-8: vacuous and missing tests

- **`tests/leaderboard.test.js`, "reads a pre-versioning queue"** — fully
  vacuous. It never called the client: it wrote a raw array to storage and read
  it back through the test's _own_ helper, which does the `Array.isArray`
  unwrapping itself. The assertion holds with `readQueue`'s migration branch
  deleted. **Fix:** assert through `flushQueue()`, and add the missing
  future-version-envelope case.
- **`tests/leaderboard-server.test.js` dashboard parity** — the CORS dimension
  was vacuous. All 9 parity cases ran with no `ALLOWED_ORIGIN`, so both workers
  were fail-closed and the compared `cors` field was `null` on every case, both
  sides. Status and body parity were real. **Fix:** set `ALLOWED_ORIGIN: '*'`.
- **`server/worker.js:125-128`** (the declared-`Content-Length` guard) is dead in
  tests: undici's `Request` sets no Content-Length, so both 413 tests are decided
  by the byte check below it. The byte-vs-character intent is still covered.
- **`sweepRateLimiter` and the hard-cap eviction** — the headline of the 0.9.5
  "bounded rate-limit map" hardening — have **zero coverage**. Verified
  empirically instead (6000 unique IPs: no growth pathology, 23 MB heap, 809 ms;
  a 7th post from one IP still 429s with `Retry-After`). An unverified guarantee,
  not a broken one.
- **`e2e/runner.mjs`'s `floor2HudSeen`** ends in `|| hud.includes('2')`, true for
  essentially any HUD. Harmless today — details string only — but written like an
  assertion.

## P3: accessibility and cosmetic

- **The death/end-run overlay is outside the modal contract the other three
  follow** (`src/ui/gameOver.js`). It builds its own shell instead of using
  `ui/overlay.js`: no `role="dialog"`, no `aria-modal`, no `tabIndex=-1`, and
  `hide()` does no focus restore. A screen-reader user gets no modal
  announcement when the run ends, and after "New run" focus lands on a button
  whose ancestor becomes `display:none`, dumping focus to `<body>`.
- **Entity sprites overflow the top of their tile**, so clicking a character's
  head in a _room_ selects the empty floor above it: `spriteOffset` gives
  `dy = -4` for the 12×15 humanoids and `-7` for the 16×18 boss. `pickClickTile`
  returns an already-walkable click untouched, so the 0.9.7 snap only rescues the
  corridor case. Clicking the boss's eye can walk you past it.
- **Floating combat text survives a floor change** — `rebuildFloor` clears the
  grid, sprites, facing and motion but not the float pool or its in-flight 450 ms
  tweens, so a hit taken 2-3 steps before the stairs finishes floating over an
  unrelated tile of the new floor.
- **Help's Ring of Shadow text contradicts the shipped rules** — "Enemies cannot
  see you until you strike them" describes the pre-0.9.6 ring, not the three
  cover-breakers that replaced it.
- **`ui/dom.js`'s `trapTabKey`** only inspects inline `display:none`, so an
  element hidden via the `hidden` **attribute** stays focusable. `menu.js` sets
  `endBtn.hidden` on the death screen; harmless only because that button is
  mid-list.
- **`motion.js`'s lunge `isActive(l.id)` guard** is annotated "never true today",
  but it also matches a previous turn's move glide still in flight, so a turn
  arriving inside 110 ms silently drops the attacker's lunge. Cosmetic; the
  comment is wrong.

## Refuted — candidates checked end to end and dropped

Recorded so they are not re-raised: Ring-of-Speed second step bypassing a rule
(the engine's repeat can only land on the node the controller already
validated); `advanceWorld`'s new conditional `updateVisibility` (the player
cannot have moved between passes, `revealRoom` is memoised, `explored` is
monotonic, no RNG); `resolveStairStep`'s new reveal call (FOV always precedes
it, `hidden` is one-way, and a floor-1 key is provably ≥4 tiles from the start);
`truncateBeforeStairs` (correct, and dead on generated floors — 0 truncations
across 7,272 plans on 720 floors, which is why synthetic tests are the right
cover); stale occupancy in the enemy phase; floor-cache desync; A\* index
collisions from `ny*width+nx`; auto-walk surviving a floor change; and all
depth-scaling, secrets-band, to-hit and armour boundaries.

Also rejected, from automated review on PR #32: "a click above the map can snap
into row 0" — it needs a walkable border cell, and the generator seals the rim
(0 walkable border cells across 120 generated floors). Converted into a tested
invariant rather than left as prose.

**Correction to this report's own P1-3 deferral (v0.9.9).** The paragraph above
originally deferred P1-3 on the grounds that "whether already-installed clients
recover cannot be answered from a repository." That reasoning was wrong, and is
left here rather than rewritten because this file is a historical snapshot. It
holds for the _move the files_ fix, which changes asset URLs — but not for the
one that shipped: narrowing `dontCacheBustURLsMatching` to Vite's real chunk
